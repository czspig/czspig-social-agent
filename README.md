# 暖暖猪

替你盯着飞书消息的个人助手。它以你本人的身份读取消息，分清轻重：要紧的立刻提醒，不急的攒成简报，其余的替你挡下。它只提醒你，不会替你回复任何人。

## 现在能做什么

| 功能 | 说明 |
|------|------|
| 消息分级 | 规则先筛，拿不准的交给模型。分为「要马上看」「晚点汇总」「不用看」三档 |
| 即时提醒 | 紧急消息弹系统通知，并推一张卡片到飞书 |
| 定时简报 | 按设定的时间点汇总不急的消息 |
| 纠正与规则 | 在消息上点「暖暖判断得不对」，可以只改这一条，也可以让它记住这个人或这个群 |
| 免打扰 | 时段内只放行最要紧的消息，结束后一起告诉你 |
| 待办 | 从消息和会议里提取别人请你做的事，识别截止时间，快到期时提醒 |
| 每日早报 | 今天要做什么、谁在等你、哪些已超期 |
| 回复辅助 | 给消息起草回复、把大意改写成得体的话，都由你自己复制去发 |
| 会议纪要 | 粘贴文字稿，整理出结论、待办、负责人和时间；分给你的事自动进待办 |
| 周报 | 根据本周处理过的消息、完成的待办和会议生成草稿，每条标注出处 |
| 找人 | 描述想办的事，从你的消息和通讯录笔记里找出最可能对口的人，并起草一句开场白 |
| 托盘常驻 | 关掉窗口后继续在后台盯消息，托盘图标上右键可以退出 |
| 深色模式 | 跟随系统，也可以在设置里固定浅色或深色 |
| 首页 | 轮播小语、每日一首歌、基于实际情况的关心（一天最多三次） |

没有配置模型密钥时，分级按规则判断，回复、纪要和周报按固定句式生成，功能都可用，只是没那么自然。

## 运行

需要 Node.js 22 或更高版本。

```bash
npm install
npm run build
npm start
```

开发时用 `npm run dev`，改界面会热更新。`npm test` 运行核心逻辑的单元测试。

第一次启动是演示模式，里面的消息都是示例，每 40 秒会来一条新的。

如果 Electron 下载失败，先设置镜像再安装：

```bash
ELECTRON_MIRROR=https://cdn.npmmirror.com/binaries/electron/ npm install
```

## 接入真实的飞书

1. 在[飞书开放平台](https://open.feishu.cn/app)创建一个企业自建应用，开启机器人能力。
2. 在「权限管理」里申请：`im:message:readonly`、`im:chat:readonly`、`contact:user.base:readonly`、`offline_access`，并申请发消息的权限 `im:message:send_as_bot`。读取消息的权限需要企业管理员审批。
3. 在「安全设置」里添加重定向 URL：`http://127.0.0.1:4317/api/feishu/callback`（以设置页显示的为准）。
4. 在「事件与回调」里选择长连接方式，订阅 `im.message.receive_v1`，并添加回调 `card.action.trigger`。
5. 发布应用版本。
6. 打开暖暖猪的设置页，填入 App ID 和 App Secret，点「用飞书登录」。
7. 点「发一条测试消息到飞书」确认能收到，再关掉演示模式。

在飞书里私聊这个机器人，发「简报」「待办」「紧急」可以随时查看。

如果应用批不下来，可以只填一个群机器人的 webhook 地址作为推送出口，但这种方式读不到消息，只能配合手动导入的会议纪要使用。

## 接入模型

在设置页填入 Claude API 密钥。默认模型是 `claude-opus-5-5`；消息量大时可以改成 `claude-haiku-5-5`。只有规则拿不准的消息才会发给模型，你标记为「不读取」的会话不会被分析。

## 结构

```
src/core      核心服务：存储、分级、调度、飞书、模型，一个只监听本机的 HTTP 服务
src/main      Electron 外壳：启动核心服务、开窗口、发系统通知
src/renderer  界面：React
src/shared    两端共用的类型
```

界面只通过 `/api` 和核心服务通信，所以以后做手机端时可以复用同一套接口。

数据存在本机的 SQLite 文件里（Windows 上是 `%APPDATA%/czspig-social-agent/data`）。密钥在 Electron 里用系统的安全存储加密后保存。

## 还没有验证的部分

- **飞书接入**（`src/core/feishu.ts`）按开放平台文档编写，没有对着真实租户跑过。登录、拉取消息、推送卡片、卡片按钮回调都需要用真实应用验证，权限名和接口路径可能要调整。其中私聊消息能否通过会话列表接口拉到，需要重点确认。
- **模型调用**（`src/core/llm.ts`）通过了类型检查，没有用真实密钥跑过。
